使い方

  1. APIキーを設定（Opus なら小サイズ生成は無料枠内）。
  2. 左側で基礎プロンプト・キャラプロンプト・ネガティブを編集。
  3. 必要に応じて参照画像を追加（バイブス＝画風 / 精密参照＝キャラ一貫性）。

プロンプトの構造

PROMPTS の「キャラ枠で送信」をオンにすると、次の 3 区分で送られます。

基礎＝基礎プロンプト ／ 基礎ネガティブ（画面全体に効きます）
キャラ枠＝キャラクター＋表情 ／ キャラ共通ネガティブ＋表情共通ネガティブ

キャラクターと表情はひとつの枠にまとめて入るので、表情ごとにプロンプトを差し替えても、キャラの外見指定は同じ枠に留まります。ネガティブも同じ分け方で、「このキャラには角を生やさない」といった指定が背景に波及しなくなります。

表情ごとのネガティブは各表情カードの NEG 欄に入力します。キャラ共通ネガティブと連結されてキャラ枠の除外指定になります。たとえば笑顔の表情にだけ closed eyes を入れておけば、その表情のときだけ目を閉じさせない、といった調整ができます。表情の複製・セットの書き出し／読み込み・他プロジェクトからの複製でも、この欄の内容は一緒に運ばれます。

オフにすると従来どおり、すべてが 1 本の文字列に連結されます。ネガティブも基礎に合流します。

注意：キャラ枠は本来「複数キャラの描き分け」のための仕組みで、モデル内部でのタグの扱いが変わります。オンとオフでは同じシードでも別の絵が出ますし、キャラ側のタグは背景や画風に影響しにくくなります。途中で切り替えると、それまでの表情差分と絵柄が揃わなくなる点にご注意ください。

座標指定（複数キャラを画面のどこに置くか）は立ち絵用途では不要なため、中央固定・記述順で送っています。

プロンプト一括編集

表情リスト上部の「プロンプト一括編集」から、選択した表情またはすべての表情に対して、文字列をまとめて挿入・削除できます。編集先はプロンプト欄と NEG 欄のどちらかを選べます。

挿入は末尾か先頭を選べ、「カンマで区切る」をオンにすると区切りの , が自動で入ります（末尾挿入なら文字列の前、先頭挿入なら後ろ）。オフにすると何も挟まずそのまま連結されるので、語尾に :1.2 のような重み指定を足したいときに使えます。「重複を避ける」をオンにすれば、すでに同じ内容が入っている表情は変更されません。

削除では「タグ単位で一致」が既定でオンになっています。この状態ではカンマ区切りの 1 要素と完全一致したものだけが消えるため、smile を削除しても smiling や smile, open mouth の open mouth は残ります。オフにすると単純な文字列置換になり、語の一部にも当たります。余分になったカンマは自動で整理されます。

実行前にプレビューで変更前後が確認でき、実行後もモーダルを開き直せば「直前の一括編集を元に戻す」で 1 回分だけ取り消せます。

表情テンプレート（全プロジェクト共通）

ツールバーの「📚 テンプレート」から、表情をブラウザ内のライブラリに保存しておけます。ライブラリはプロジェクトに属さないので、どのプロジェクトからでも呼び出せます。バリエーション・NEG・無効化タグもまとめて保存されます。

「表情」タブは 1 件ずつのテンプレート、「セット（組み合わせ）」タブは複数の表情をひとまとめにしたものです。セットは「＋ セットを追加」で現在の表情の末尾に足すか、「置き換え」で丸ごと入れ替えられます（置き換えると生成済み画像も消えるため確認が入ります）。

各表情カードの 📚 を押すとその表情をテンプレートに保存、ライブラリ側の「現在の表情から保存」では選択中の表情（未選択なら全表情）をまとめて保存できます。ライブラリ全体は JSON で書き出し／読み込みができるので、別の PC へも持ち込めます。

プロンプトのバリエーション

ひとつの表情に複数のプロンプトを持たせられます。表情カードの「▸ バリエーション / 無効化」を開いて「＋ バリエーションを追加」で増やします。1 番目は上のプロンプト欄と同じもので、常に連動します。ラベルを付けておくと、どの候補から生成された画像かサムネイルの左下に表示されます。

候補が 2 件以上あると「選択」欄が出ます。1番目（既定）は常に先頭を使い、ランダムは 1 枚ごとに無作為に選び、順番は上から順に使って末尾まで行くと先頭へ戻ります。順番のときは次に使う候補がバッジに出て、クリックすると先頭に戻せます。

表情ごとのプロンプト無効化

同じカードの下側で、その表情のときだけ送信プロンプトから消したいタグを指定できます。ネガティブとは違い、送る文字列から実際に取り除きます。たとえば基礎プロンプトやキャラプロンプトに smile が入っていても、「怒り」の表情に smile, happy を登録しておけば、その表情の生成時だけ両方が外れます。

比較はカンマ区切りのタグ単位で、{smile} や 1.2::smile:: のような強調・重み表記も同じタグとして扱います。smil* のように * を書けば前方一致などのワイルドカードになります。「部分一致」をオンにすると open mouth smile の中の smile だけを削るような動きになります。

対象は「基礎＋キャラプロンプト」が既定で、「基礎のみ」「キャラのみ」「表情プロンプトも含む」から選べます。実際に何が消えるかはその場に表示され、👁 ボタンを押せばバリエーションごとの最終的な送信内容を確認できます。

キャラクターと画像

生成した画像はキャラクターごとに保存されます。キャラクターを切り替えると、そのキャラクターで生成した候補だけが表示され、以前のキャラクターに戻せば元の候補が戻ります。採用・保留・フィルター・ZIP 書き出し・一括削除も、すべて表示中のキャラクターが対象です。

生成キューは投入した時点のキャラクターを記憶します。生成中にキャラクターを切り替えても、実行中のジョブは元のキャラクターのプロンプトで生成され、そのキャラクターの下に保存されます。

キャラクターを削除すると、そのキャラクターの画像もあわせて削除されます（確認が入ります）。以前のバージョンで生成した画像は、最初のキャラクターのものとして引き継がれます。

参照画像

バイブス：画風・色調・雰囲気を抽出します。Info Extracted で抽出量、Strength で反映強度を決めます。エンコードしておくと生成のたびにかかる 2 Anlas を節約できます（Info Extracted を変えると再エンコードが必要です）。各カードの「💾 書き出し」で .naiv4vibe 形式に書き出せます。NovelAI 本体のバイブス形式と互換なので、本体で作ったファイルを読み込んだり、逆に持ち込んだりできます。エンコード済みデータもファイルに含まれるため、別の PC でも再エンコードなしで使えます。

精密参照：キャラの外見の一貫性を保ちます。まず 1 枚気に入った画像を生成 → 📌 で精密参照に登録 → 残りの表情を生成、という流れが基本です。Strength は再現の強さ、Fidelity は参照をどれだけ厳密に守るか（高いほど参照に忠実で、プロンプトで上書きしにくくなります）。「画風も参照」を入れると絵柄も引き継ぎます。参照画像は API が要求する規定サイズ（1024×1536／1472×1472／1536×1024 のうち、元画像の縦横比に最も近いもの）へ自動で変換されます。1 枚につき 5 Anlas の追加費用がかかります。

各表情のカードには参照画像のトグルが並び、その表情で使う参照だけを選べます。各セクションの「全表情でオン／オフ」を押せば、その種類の参照をすべての表情に対してまとめて切り替えられます。参照あり・なしを比べたいときに便利です。

バックグラウンドでの生成

Chrome や Edge は、裏に回ったタブのタイマーを抑制します。まず 1 秒の下限がかかり、5 分ほど非表示のままだとタイマーが 1 分に 1 回程度しか動かなくなります。生成リクエスト自体は抑制されないため、止まって見えるのは「次の 1 枚までの待ち時間」が数十倍に伸びるからです。

GENERATION の「バックグラウンド維持」をオンにすると、生成中だけ無音に近い音声を再生します。音を出しているページは抑制とタブ凍結の対象外になるため、裏に回しても速度が保たれます。実際に音は聞こえませんが、タブに音量アイコンが表示されます。あわせて待機処理を Worker のタイマーに移し、絶対時刻で待つようにしているので、タイマーが遅れて起きても遅れ分が積み上がりません。

それでも抑制が強くかかった場合はメッセージでお知らせします。確実なのはウィンドウを表示させたままにすることです。最小化や別ウィンドウで完全に覆うと非表示扱いになるので、小さくしてどこかに置いておくのが有効です。生成が終わるとデスクトップ通知でお知らせします（初回に許可を求めます）。

未エンコードのバイブス

バイブスは「モデル × Info Extracted」の組み合わせごとにエンコードが必要で、未エンコードのまま送ると API がリクエスト自体を拒否します。そこで生成を始める前に、これから作る表情で未エンコードのバイブスが指定されていないかを確認します。見つかった場合は確認画面が出て、エンコードしてから生成（1 件につき 2 Anlas）、このバイブスを外して生成（対象の表情でそのバイブスをオフにします）、キャンセルから選べます。

チェックの対象は、そのとき生成する表情でオンになっているバイブスだけです。オフにしてある表情や、今回生成しない表情でしか使っていないバイブスは、未エンコードでも生成を止めません。モデルや Info Extracted を後から変えた場合も、エンコードが古くなるので同じ確認が出ます。

保留フラグ

採用は各表情 1 枚のみですが、保留は複数付けられます。迷ったらまず保留 → フィルターで保留だけ表示して比較 → 最終的に 1 枚を採用、という流れに。「保留画像を ZIP 保存」で保留だけの書き出しも可能です。

バックアップ / 復元

ヘッダーの 💾 でプロジェクト設定（プロンプト・参照画像・表情セット）を JSON 書き出し。📂 で別ブラウザや別 PC に復元。生成済み画像は含まれません。

生成の実行

生成順序：GENERATION の「生成順序」で 2 通りから選べます。「表情ごとにまとめて」は、ひとつの表情を規定枚数ぶん作ってから次へ進みます。「1 枚ずつ交互に」は全表情を 1 枚ずつ一巡し、それを規定枚数ぶん繰り返します。後者なら途中で止めても全表情が均等に埋まるので、まず 1 周ぶんを見て方向性を確かめたいときに向いています。

上部のツールバーには 3 種類の生成ボタンがあります。「未生成の表情のみ」は、まだ 1 枚も画像がない表情だけをまとめて生成します（対象の件数がボタンに出ます）。追加した表情だけを埋めたいときや、途中で中止した続きから再開したいときに便利です。「選択した表情を生成」はチェックを入れた表情だけ、「全表情を生成」はすべての表情が対象です。

表情の追加・削除

上部のツールバーは画面に固定されているため、「＋ 表情を追加」を続けて押していけばまとめて追加できます。横の数値欄に数を入れておけば、一度に複数まとめて追加することも可能です（押した位置は動かないので、そのまま連続で押せます）。リストの末尾にも同じボタンがあり、そちらは追加した表情までスクロールして名前欄にカーソルを合わせます。各表情の「＋」を押すと、その直下に新しい表情を挿入できます。

各表情の左端のチェックボックスで選択できます。「すべて選択」「選択を解除」「選択を反転」と「選択した表情を生成」は上部のツールバーにまとまっています。選択すると、その下に削除用のバーが現れます。

キーボードとマウスの近道

表情カードのプロンプト・NEG・バリエーションなどの入力欄で Ctrl+Enter（Mac は ⌘+Enter）を押すと、その表情だけを生成します。入力欄から手を離さずに、書き換えた結果をすぐ試せます。

サムネイルを右クリックすると、その場に操作メニュー（拡大表示・採用・保留・参照への登録・シードのコピー・削除）が開きます。小さなボタンを狙う必要はありません。

サムネイルの大きさは、フィルターの右にある「サイズ」で変えられます。サムネイルの上で Ctrl+ホイールを回しても変わります。この設定はブラウザに保存され、すべてのプロジェクトで共通です。

画像ビューのショートカット

サムネイルをクリックして開いた拡大表示では、次のキーが使えます。

← → 前後の画像へ／↑ ↓（または Q E）前後の表情へ／A または Enter 採用（採用済みならもう一度押すと取り消し）／S または H 保留（もう一度で解除）／D または Delete 削除（確認が出るので Enter で確定）／C シード値をコピー／Esc 閉じる

シード値は画面には表示していませんが、C か「シード」ボタンでいつでもコピーできます。

上下キーを使えば、拡大表示を閉じずに表情をまたいで選別を進められます。移動先の表情名と候補の枚数が画面中央に一瞬表示されます。候補が 1 枚もない表情は自動的に読み飛ばされ、最後の表情から先へ進むと最初の表情に戻ります。フィルターを「保留」にしておけば、保留中の画像だけを表情順に見ていくこともできます。

採用と保留は排他です。採用すると保留は外れ、保留にすると採用は外れます。どちらも同じキーをもう一度押せば解除できるので、選び直しも自由にできます。矢印キーで送りながら A と S を押していけば、マウスに触れずに選別できます。

拡大表示中は、採用した画像は緑、保留中の画像は黄色の枠で囲まれ、左上にも印が出ます。送りながらでも今どちらを付けたか一目で分かります。

候補を一巡して最初の画像に戻ると、画面の中央に案内が出て枠が一瞬光ります。全部を見終えたことがすぐ分かります。

拡大表示を閉じると、最後に見ていた表情と画像の位置までページが移動し、その表情のカードが一瞬光ります。上下キーで表情をまたいで選別したあとでも、続きの場所を探し直す必要はありません。

画像の削除とストレージ

画像は削除するとブラウザのデータベースから実際に消えます。ゴミ箱のような復元領域は持っていないため、消したものは戻せません（書き出し済みのファイルは残ります）。

ただしブラウザ側の都合として、削除直後にディスクの空き容量がすぐ増えるとは限りません。ブラウザはデータベースの空き領域をしばらく保持し、あとでまとめて回収します。使用量が気になるときは、ブラウザを再起動するか、しばらく使っていれば自然に解放されます。完全に消したい場合は、ブラウザの設定からこのページのサイトデータを削除してください（その場合はプロジェクトごとすべて消えます）。

ファイル名規則

書き出される画像のファイル名は キャラ名_表情名.png です。キャラクターを切り替えれば、そのキャラの名前で保存されます。同じ表情に複数の画像がある場合は _1 _2 の連番が付きます。

EXPORT の「カスタム命名を使用する」をオンにすると、区切り文字を自由に変えられます（_ - 半角スペースなど。空にすれば Hanakosmile.png のように直結します）。また PROMPTS セクションに「書き出し名」の欄が出るので、日本語のキャラ名とは別に Hanako のような英数字名を指定できます。設定した内容はプレビューで確認できます。

ZIP ファイル自体の名前は プロジェクト名_キャラ名_種別.zip になります。

リトライジッター

ON にすると 429 レート制限時の待機時間（15秒から始まり、続けて制限されると 30秒・60秒と延び、6回続くと生成を中止します）にランダムな秒数を加えます。加算範囲は小数点第2位まで自由に設定でき（例: 0.50〜8.00秒）、複数タブで同時に回す場合の衝突回避に有効です。
